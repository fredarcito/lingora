# Interfaz multilingüe (i18n)

Estado a 2026-10-29: español e inglés incluidos; cualquier otro idioma de `LANGS`
se genera en el equipo con el modelo de traducción local.

No confundir con los idiomas **de traducción** (`LANGS` en
`src-tauri/src/config.rs`, 37 idiomas): aquí se trata de en qué idioma se ve la
**interfaz**. Son independientes: alguien puede usar la interfaz en español y
traducir entre francés y japonés.

## Por qué está hecho así

- **Instalador pequeño.** No se traen 37 archivos de traducción: solo `es` y
  `en`. El resto se genera una vez con HY-MT2, que ya está en la app (todo local,
  sin nube; ver CLAUDE.md §3).
- **Sin dependencias nuevas.** Es un módulo propio de ~150 líneas en vez de
  `react-i18next` (CLAUDE.md prohíbe añadir paquetes sin preguntar).
- **Todo en el frontend.** La generación usa el comando `translate` que ya existía
  y guarda en `localStorage`. No se tocó `src-tauri` (editarlo reinicia
  `tauri dev`). Si algún día se mueve a un archivo en disco, hará falta un comando
  nuevo en Rust.

## Archivos

| Archivo | Qué hace |
|---|---|
| `src/i18n/index.jsx` | Motor: `t()`, `useT()`, `useLang()`, `I18nProvider`, almacenamiento de idiomas generados. |
| `src/i18n/es/<ns>.json`, `src/i18n/en/<ns>.json` | Textos. Un archivo por pantalla o módulo (el nombre es el espacio de nombres). |
| `src/i18n/generate.js` | Traduce `en` a otro idioma con el modelo local. |
| `src/LanguagePicker.jsx` | Selector en Ajustes → Interfaz (incluidos, generados, «Generar otro idioma…»). |
| `src/LangOffer.jsx` | Aviso de una sola vez al arrancar si el sistema está en un idioma que se puede generar. |

## Cómo se usa

- Los JSON son planos; la clave final es `<archivo>.<clave>`: `sidebar.json` con
  `"menu"` → `t("sidebar.menu")`.
- Variables con `{nombre}`: `t("settings.version", { version })`.
- Plurales: claves `clave_one` / `clave_other` y `t("clave", { count: n })`
  (`Intl.PluralRules` elige la forma; si falta, cae a `_other`).
- Nombres de idioma: Rust los manda en español. `App.jsx` pasa a las vistas
  `shownLanguages`, con el nombre en el idioma de la interfaz (`langName`, que
  usa `Intl.DisplayNames`). `languagesRef` sigue con los de Rust: lo usa `start`.
- En componentes: `const t = useT();` (repinta al cambiar de idioma). Fuera de
  React (`notes.js`, `api.js`): `import { t } from "./i18n"`. Ojo: ese `t` no
  repinta; solo sirve para textos que se calculan al mostrarse.
- Resolución: idioma generado → idioma incluido → **inglés** → la propia clave.
  Una clave sin traducir nunca deja la pantalla vacía.
- Textos de módulo (constantes con etiquetas): guarda solo el id y llama a `t()`
  al renderizar. Si guardas el texto ya traducido, no cambia al cambiar de idioma.

## Regla al añadir o cambiar textos

1. Añade la clave **en `es/` y en `en/`** del mismo archivo. Las dos deben tener
   exactamente las mismas claves (comprobación sugerida: comparar los conjuntos de
   claves de cada pareja de archivos).
2. `en` es la **fuente de la generación**: lo que se traduce a otros idiomas es
   `en`. Escribe un inglés corto y claro; es lo que verá el modelo.
3. Los idiomas ya generados no se enteran: las claves nuevas aparecen en inglés
   hasta que el usuario pulse «Volver a generar» (idea pendiente: detectar claves
   que faltan y traducir solo esas).
4. No pongas nombres de modelos en los textos (CLAUDE.md §3).

## Detección del idioma

`navigator.language` reducido al código base (`es-MX` → `es`). Si es `es`, español;
si no, inglés. Lo elegido a mano se guarda en `lingora.uiLang` y manda sobre el
del sistema. Un valor guardado que ya no existe (idioma borrado) se ignora.
Árabe, hebreo, persa y urdu ponen `dir="rtl"` en `<html>`; el CSS no está
revisado para RTL.

Las dos ventanas (principal y subtítulos flotantes) comparten `localStorage`; el
evento `storage` actualiza la otra al cambiar de idioma.

## Cómo se genera un idioma (`generate.js`) y por qué

Se traduce **clave a clave**, de `en` al idioma, con `local = true` (HY-MT2) y una
nota de contexto («texto corto de interfaz…»). Lecciones aprendidas probando con
italiano; **no las deshagas**:

- **Los marcadores `{x}` se enmascaran.** El modelo traduce los nombres dentro de
  las llaves (`{date}` → `{data}`). Antes de traducir se cambian por `{1}`, `{2}`…
  y después se restauran. Si faltan o sobran marcadores, la clave se descarta y se
  queda en inglés. Al ir por número, el modelo puede reordenar las palabras sin
  cambiar qué valor va en cada hueco.
- **No se valida el número de comas.** Una versión previa lo hacía y descartaba
  traducciones correctas (las comas cambian entre idiomas; las palabras sueltas se
  confundían con listas).
- **Los meses no pasan por el modelo.** `notesLib.months` se saca de
  `Intl.DateTimeFormat(código, { month: "short" })`: el modelo devolvía nombres
  completos, no las abreviaturas que necesita la interfaz.
- **El servidor local puede colgarse.** Una petición lenta vence a los 30 s en Rust
  y `llama-server` se relanza; las peticiones de ese intervalo fallan. Por eso cada
  clave se reintenta una vez (con `translateWarmUp`) y al final hay un repaso de las
  que quedaron en inglés.
- **Solo es secuencial.** Hay una sola instancia de `llama-server`; ~355 claves
  tardan unos minutos.
- Cada clave descartada o fallida se anota con `console.warn("[i18n <código>] …")`
  con el motivo: mira la consola de la ventana (no la terminal de `tauri dev`).

Almacenamiento: `lingora.uiStrings.<código>` = `{ strings, date, missing }`. Si
no cabe en `localStorage`, `saveGenerated` lanza y el selector lo muestra como
error.

## Pendiente

- **Textos que llegan de Rust en español:** `title` y `detail` del diagnóstico
  (`doctor.rs`), errores (`error.rs`) y los encabezados exportados de las notas
  («## Resumen», «## Transcripción» en `notes.rs`). Hay que mapearlos por id/código
  y no por texto. `Diagnostics.jsx` compara `c.fix === "Descargar"` con el texto
  que manda Rust: debería ser un id.
- **Calidad de la traducción automática:** sale algo literal («Il linguaggio di
  Lingora è mostrato qui»). Ideas: una nota de contexto por clave (`_ctx`) y un
  glosario (interfaz, traducir, notas, ajustes).
- **Claves nuevas en idiomas ya generados:** traducir solo las que faltan.
- **Lista de respaldo** de `App.jsx` (`{ code: "es", name: "Español" … }`) con
  nombres fijos; solo se ve si falla la carga de idiomas.
- **RTL:** revisar el CSS para árabe y hebreo.
- **Aviso de arranque:** solo compara el código base, así que `zh-TW` no coincide con
  códigos como `zh-hant` de `LANGS`.
- **No se ha medido** el tiempo ni la calidad de la generación para idiomas con
  escritura no latina (japonés, árabe, tailandés…).
